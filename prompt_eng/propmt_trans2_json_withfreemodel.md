前置文件：`chain_byprompt.yaml=思路构思`，`chain_datadic.md=数据字典`

术语定义：

请仔细理解这个`思路构思`，并根据这个`思路构思`的结构，生成思路的描述文档。
改写的规则如下：
Step 1：明确`思路构思`的意图（目标）
•	解读`思路构思`的真实意图与内容逻辑；只保留内容相关的生成规则；
•	提炼出“该`思路构思`想解决的问题”以及“希望产出的内容形式”。

Step 2：抽取其中的变量
•	识别`思路构思`中涉及的内容组成单位；
•	每一个“概念单位”抽象为变量；
•	所有变量必须依次记录进 varList（即变量清单）；
•	用户提供的第一个变量固定命名为 ThinkPoint。

Step 3：理清变量生成的因果顺序
•	以 ThinkPoint 为起点，构建变量之间的生成链；
•	所有变量必须有清晰的前置依赖关系（除 ThinkPoint）；
•	构成整个“思路”的路径（step-by-step chain），这个路径体现为变量间的依赖关系。

•      依赖关系的示例如下：`dependencies = { "X": ["ThinkPoint"], "Y": ["X"], "Z": ["X", "Y"] }`

Step 4：构建分步逻辑链
•	将整个`思路构思`拆解为多个步骤（step），每一步只描述各个变量的转换、生成机制。

•       根据依赖关系来构建步骤和步骤之间的关系；
•	每一步能使用多个输入变量，只能生成一个输出变量，输入变量和输出变量在描述文档里面的使用需要符合格式规定，用{{}}扩起来；
•	每一步的 `思路构思`中的原始指令应根据输入/输出逻辑改写；
•	每一步必须产出一个明确的结果，这个结果就是这一步的输出变量，这个输出变量的赋值动作需要在描述文档的stepprompt中写出来；
•      这些步骤的具体执行方法应写入stepprompt字段，每个变量生成完毕后写入 varList。

Step 5：以符合数据字典的 JSON 输出结果
•	输出为一个整体思路的描述文档的JSON对象，字段必须参考`数据字典`，填写默认值的按默认值生成，默认值为null的不生成：

•      依赖关系不作为JSON内容输出。

•      检查所有step中的preID和nextID，如果出现不一致的情况，请参照依赖关系重新调整，确保step的顺序描述的一致性
