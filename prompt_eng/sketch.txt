# Model-Chain-Think Prompt: <<name_of_chain>> (based on <<name_of_model>>)

Model-Chain-Think (MCT) is a structured thinking framework that enables chained thinking and clear result generation through LLMs. It consists of three parts: Model, Chain, and Think, which define the thinking framework, execution process, and generated results, respectively. MCT includes structured format requirements and action instructions that the LLM must adhere to.

  ## Principle and Terms

  - Model: Defines the framework structure of a highly abstract thinking model.
    - Entity Prompt: Defines all entities (Model Entity) of the Model and their predicate relationships (Model Predict).
    - Graph Prompt: Defines the geometric model, presentation methods, etc., of Model Entities and Model Predicts.
    - Example: The dual-factor orthogonal model and the triangular exclusion model are examples of thinking models.
  - Chain: Defines the specific thinking process flow that conforms to a certain thinking model framework.
    - Composition: Consists of several thinking steps (Think Step) and flow control steps (Control Step).
    - Chain Steps:
      - 1) Include ID, Name, Type (Think | Conditional | Loop | Sub-process), Input/Output Entity Variables, Description, and Execution Instructions.
      - 2) Execution Rules:
        - Before a step runs, the ID of the currently running step must be stated.
        - Automatically check input variables; if missing, prompt the user and wait for input.
        - Use the `start` command to execute steps sequentially, e.g., `start: [step_id-1, step_id-2 ...]`.
    - Chain Entity Variables (Entity):
      - 1) Include: Name, Description, Format, Type (Single Value String, Multi-Value List, Dictionary Dict).
      - 2) Each step includes one or more Input Entities and one Output Entity. Input entities are the source for generating the output entity.
      - 3) ThinkPoint Entity: The first step of the Chain requires a single-value type ThinkPoint as input.
      - 4) Format:
        - 1) The TBL format for an Entity is a multi-record table (using CSV format: use "##" to separate fields).
        - 2) Can record the generation source of each record (maintaining reference relationships between variables, linked through fields with "ID").
    - Chain Predicates:
      - 1) The relationship between the Input Entity and Output Entity of a thinking step is a predicate relationship, named after the thinking step.
    - Chain and Model Mapping:
      - 1) Each Chain must declare the Model it adheres to.
      - 2) All Model Entities of that Model must have corresponding Chain Entities in the Chain.
      - 3) Between Chain Entities modified by Model Entities, add Model Predict as Chain Predict.
    - Example: SWOT analysis method (a Chain conforming to the dual-factor orthogonal model), PEST analysis method (conforming to the triangular exclusion model) are examples of thinking method chains.
  - Think: The result generated by the LLM executing according to MCT requirements for a specific thinking point (ThinkPoint).
    - Think Entity: The TBL result corresponding to the Chain Entity output by the LLM after executing MCT according to the Chain's requirements is the Think Entity.
    - Think and Chain Mapping: Each Think Entity can be mapped to a Chain Entity and the corresponding Model Entity.
    - Example: Using the SWOT analysis method (a Chain conforming to the dual-factor orthogonal model) to analyze the ThinkPoint proposed by the user (e.g., "Under the current trend of anti-globalization, replace bonds and stocks with US dollars and gold"), and obtaining the RDF result.
